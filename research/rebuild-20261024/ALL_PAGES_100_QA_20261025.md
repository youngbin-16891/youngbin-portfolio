# 전 페이지 100개 QA 시나리오 — 2026-10-25

## 범위와 방식
공개 메인에서 연결을 따라 발견한 HTML 10개를 대상으로 했다: 메인, A/B/C 상세, A/B/C 요약, 결과물 목록, 초기 감사, 초기 출처 대장. 관계없는 별도 앱·숨겨진 로컬 작업 폴더는 포트폴리오 페이지에 포함하지 않았다.

Windows Chrome에서 viewport/터치/색상 환경을 지정해 실제 URL을 열고 캡처했다. 실기기 100대나 무작위 사용자 100명을 조사한 것이 아니라, 아래 100개 결정적 검사 시나리오다.

80개 화면 검사에서 페이지 로딩 상태, pageerror/콘솔 오류, 실패 HTTP 리소스, 문서 전체 scrollWidth, 이미지 로딩, 테이블 내부 스크롤을 검사했다. 첫 화면과 부록 전체를 펼친 전체 화면을 각각 캡처했다. 밝은 화면과 430/1024px의 어두운 화면을 포함했다.

## 발견한 문제와 수정
1. `reports/index.html`, `audit.html`, `source-ledger.html`은 탭 아이콘이 지정되지 않아 기본 `/favicon.ico`가 404를 낼 수 있었다. 기존 메인 YB 아이콘을 그대로 연결했다.
2. 결과물 목록에서 연결된 초기 감사·출처 대장이 현재 제출본의 평가처럼 읽힐 수 있었다. 초기 감사에는 C의 VOC를 아직 수집하지 않았다는 과거 기록 등이 남아 있었다. 기록 자체는 보존하되 제목·링크를 초기 기록으로 명확히 바꾸고, 현재 상태가 아님을 상단에 표시했다. 최신 근거·결과물은 각 보고서로 연결했다.

A/B/C 본문·요약·PDF·메인 디자인·플레이 기록·연락처 값은 수정하지 않았다. 빈 영역·이미지 실패·문서 전체 가로 넘침은 발견하지 못했다. 긴 표 내부 스크롤은 정상 동작으로 유지했다.

재생성 시 동일 수정이 유지되도록 `polish-auxiliary-pages.mjs`를 통합 빌드 마지막에 연결했다. 기존 분석을 덮어쓰는 작업은 하지 않았다.

## 최초 검사와 재검사
최초 80개 화면 검사는 모두 HTTP200, 이미지 실패/전체 가로 넘침 없음. 초기 감사 진입에서 favicon 콘솔404가 기록됐다. 동작20개는 모두 통과했다. 이후 보조 페이지 수정을 배포하고 동일 100개를 재실행한다. 원본 결과/화면은 outputs/final-100/, 재검사 화면/행렬은 outputs/final-100/after/에 기록한다.

## 검증 한계
- 모바일/태블릿은 Chrome의 viewport·터치 시뮬레이션이며 iOS Safari/Android Chrome 실기기·물리 태블릿은 아니다.
- 인쇄 버튼의 window.print 호출을 확인했다. 운영체제 저장 대화상자/물리 인쇄를 자동 검사했다는 뜻은 아니다.
- PDF는 실제 다운로드와 기존 원본 일치를 확인한다. 브라우저마다 미리보기로 열리는 차이는 오류로 취급하지 않는다.
- 메일 검사는 기존 mailto 대상과 활성화까지이며 메일 발송·외부 앱 연동 성공은 미검증이다.
- 모든 외부 출처의 향후 가용성이나 모든 브라우저 버전의 무오류를 보장하지 않는다.
