# C. 메이플 키우기 — 환불 이슈와 신뢰·이탈 위험 대응

### 1. 먼저 내린 판단
- 실제 사건: 유료 기능의 안내·적용 오류와 고지 문제 이후 전액 환불 신청 절차가 운영됐다.
- 운영 문제: 금전 처리뿐 아니라 신청 직후 계정 제한, 취소 조건, 처리 상태를 이용자가 정확히 이해해야 한다.
- 우선 대응: 진행 중 피해를 확인하고, 정책·신청 화면·FAQ·CS 답변을 먼저 맞춘다. 새로운 보상을 먼저 제안하지 않는다.
- 작성 결과물: 사건 타임라인, VOC 분류, 우선순위, 모의 공지·FAQ·CS 기준, 환불 검토표, 사후 측정 계획.
- 사후 지표: 처리 완료 시간·미처리·재문의와 활동 변화를 분리한다. 환불로 제한된 계정의 미접속을 자발적 이탈로 세지 않는다.

공개자료를 바탕으로 작성한 신입 지원자의 모의 운영 과제다. 실제 회사에서 수행한 업무나 내부 절차가 아니다. 조사 기준일은 2026.10.24. 아래 공지는 당시 상황을 가정한 연습용이며, 현재 환불을 신청하라는 안내가 아니다.

### 3. 공개 VOC: 전체 여론이 아닌 문의 쟁점 탐색
VOC는 이용자가 표현한 의견·문의다. 기존에 수집한 인벤 기사 S4의 공개 댓글 한 스레드를 사용했다. 수집 대상 기간은 01.28~02.15, 확인 댓글의 게시일은 02.02~02.09다. 15개 댓글 중 관련 9개를 포함하고 6개를 제외했다. 같은 작성자의 답글이 포함되므로 9명의 이용자가 아니다.

검색에서 접근 가능한 반대 의견이 함께 있는 글을 고른 목적 표집이다. 환불·계정 영향·신뢰와 관련된 원문만 포함하고, 무관한 게임·인신공격만 있는 댓글 등은 제외했다. 댓글 ID로 중복을 제거했다. 전체 목록과 제외 사유는 아래 CSV에 보존했다. 유형별 비율·빈도 순위는 제시하지 않는다.

| 검토 유형 | 실제 수집 사례 / 근거 수준 | 운영 문서에 반영할 질문 |
|---|---|---|

### 4. 먼저 해결할 안내 위험
S6의 최초 공지는 환불 처리 완료 후 게임 제한을 설명하지만 S3은 신청 완료 즉시 제한을 안내한다. 따라서 초기 공지만 읽은 사람에게는 신청 전 최신 조건을 다시 확인시키는 절차가 필요하다는 가설을 세웠다. 실제 혼동 빈도는 모른다.

S3의 현행 영문 FAQ에는 두 표현 차이도 확인된다. 철회는 앞부분에서 ‘신청 기간 내’, 뒤에서는 ‘처리 기간 중’으로 설명한다. 환불 가능 금액이 없는 계정도 앞부분에는 검토 후 제한 해제, 뒤에는 신청 시 영구 제한으로 쓰여 있다. 서로 다른 예외일 가능성은 있으나 문서만으로 적용 우선순위를 확정할 수 없다.

판단: 환불 정책 자체가 틀렸다고 단정하지 않는다. 정책 책임자가 예외·적용 시점을 확인한 뒤 신청 화면, FAQ, CS 답변을 같은 버전으로 정리하는 것이 우선이다. 현행 FAQ는 수정 이력이 모두 보이지 않아 당시 오안내가 실제 발생했다고 주장하지 않는다.

### 7. 모의 공지문 — 과거 상황을 가정한 초안
임시 안내: “유료 기능의 안내와 실제 적용 결과가 일치하지 않을 가능성을 확인해 조사 중입니다. 영향 기간과 대상을 확인하고 있으며 현재 확정되지 않은 환불·보상 조건은 먼저 약속드리지 않겠습니다. 확인된 범위와 조치 계획을 추가로 안내하겠습니다. 다음 안내: [책임자 승인 후 게시 전 확정할 시각]. 결제 자료는 공개 댓글이 아닌 공식 고객센터로 보내주세요.”

이 초안은 다음 안내 시각을 확정하기 전에는 게시하지 않는 검토 문서다. 조사 중에도 추가 피해가 이어지면 공지 작성과 별도로 보호 조치를 책임자에게 요청한다.

정식 공지 구성안: ①잘못된 정보·적용 현상과 기간 ②수정 및 검증 결과 ③환불 대상 결제와 시간대 ④신청 기한·게임 계정 로그인 경로 ⑤신청 즉시 제한·전체 캐릭터·닉네임 영향 ⑥철회 가능 조건과 예외 ⑦마켓 환불·기환불액 처리 ⑧진행 상태 확인·비공개 문의 ⑨후속 점검 일정. 미해결 FAQ 표현 차이는 승인 전 게시를 보류한다.

### 8. 환불 FAQ 및 CS 처리 기준
S2·S3의 영문 공지를 기준으로 정리한 과거 정책 요약이다. 한국어 고객 안내로 그대로 재사용하지 않고 해당 지역 승인본을 별도로 대조한다. 현재 신청은 종료됐다.

### 10. 사후 모니터링 — 내부 데이터가 있을 때의 측정안
아래 수치는 결과가 아닌 측정 정의다. 임의 목표치·효과는 넣지 않았다. 일자는 해당 서비스 운영 시간대로 통일하고 지역·마켓을 나눈다. 관찰 기간이 끝나지 않은 계정을 분모에 넣지 않는다.

| 지표 / 목적 | 모집단·분모 / 기간·계산 | 해석 주의 |
|---|---|---|
| 처리 완료 시간·대기 | 유효 신청 건. 접수→마켓 취소 확인까지 시간의 중앙값·상위 10% 경계, 미완료 잔량과 대기 일수 매일 확인 | 입금 확인이 없으면 취소 완료와 환급 완료를 구분. 미완료를 빼고 속도만 평가하지 않음 |
| 거래 처리·중복 | 대상 거래 ID 중 정상 취소 확인 거래 비율, 중복 처리 거래 수. 신청 시작~잔량 종료 | 계정 단위 신청과 거래 단위 정산은 별도. 대조 실패를 성공으로 처리하지 않음 |

행동 측정에서 제한 계정은 별도 상태로 표시한다. 접속 가능 계정의 행동을 비교할 때도 제한 계정 수·비중을 함께 보고해 제외로 인한 착시를 막는다. 재가입자를 개인정보 근거 없이 연결하지 않는다.

### 11. 신뢰 회복을 판단하는 순서
- 먼저: 오류·대상·계정 영향·처리 상태를 서로 맞춘다. 잘못된 안내는 수정 시각과 바뀐 내용을 남긴다.
- 다음: 거래 대조·예외 처리·재문의 검수를 반복한다. 원인 미확인 문의는 담당자와 다음 확인 시점을 남긴다.
- 이후: 수정 검증·변경 승인·공지 점검 결과를 공개 가능한 범위에서 안내한다. 활동과 반복 VOC, 동의 기반 신뢰 조사 등을 함께 본다.
- 종료: 거래 잔량과 예외를 모두 추적 가능하게 만들고 재발 검사·책임자 승인을 마친다. 환불 완료와 신뢰 회복은 같은 완료 조건이 아니다.

면접에서 설명할 판단: “환불을 더 주자는 제안보다 신청자가 무엇을 잃고 어떻게 처리되는지 정확히 알게 하는 것을 먼저 택했습니다. 특히 이용 제한 때문에 생긴 미접속을 일반 이탈로 세지 않도록 지표를 나눴습니다.”
