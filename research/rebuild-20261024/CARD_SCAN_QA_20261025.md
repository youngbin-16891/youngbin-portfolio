## 범위
`dist/deliverables.js`의 카드 설명 3개와 카드 내부 직무 위치, `dist/index.html`의 해당 스크립트 캐시 버전만 변경했다. CSS 수정은 불필요했다. 상세 보고서/요약본/PDF/Experience/About/연락처 값은 변경하지 않았다.

## 기존 상태
핵심 설명은 이미 표시되어 있었고 display:block, overflow:visible, line-clamp:none이었다. 숨김 결함은 없었다. B의 설명은 실행 전제부터 시작해 결론을 파악하기 어려웠다. 새 설명을 누적하지 않고 기존 project-finding 문장만 교체했다.

## 적용 문구와 근거
- A: **기본 패스 구매·PLUS 미구매 경험을 비교해, 진행 조건별 상품 가치와 구매 전 안내 방향을 분석했습니다.**
  - 근거: A 본문 02 실제 구매 경험, 03 BM 분석, 04 조건부 구매 전 안내. 요약본의 개인 경험·실무 제안과 일치. 전체 이용자 동기를 입증했다거나 안내 효과를 달성했다는 뜻이 아니다.
- B: **보상 수령과 경기 참여는 다릅니다. 규칙 확인과 혼선 검증 후 첫 경기 안내를 시험하는 모의안입니다.**
  - 근거: 실제 접속 보상과 경기 미션이 별도이고, 서버 인정 규칙·안내 혼선 검증이 먼저다. 안내가 경기 미참여 원인이라고 확정하거나 이미 개선 효과를 측정한 것으로 쓰지 않았다.
- C: **계정 제한에 따른 미접속은 자발적 이탈과 다릅니다. 이를 구분한 이용자 안내·FAQ·CS 모의안을 작성했습니다.**
  - 근거: 현재 공식 영문 FAQ와 C 핵심 판단, 실제 작성한 공지·FAQ·CS 과제에 근거. 실제 회사의 운영 성과로 표현하지 않았다.

직무는 이미지 뒤의 제목 영역으로 옮겼다. 모바일에서 이미지→직무→게임명/제목→판단→기존 결과물·링크가 된다. PC는 이미지 왼쪽, 직무·제목·판단 오른쪽의 기존 그리드다. 이미지·폰트·버튼 스타일은 유지했다.

각 너비에서 보고서3·요약3의 실제 클릭/터치 후 목적 URL 확인, pageerror 0. 375px viewport에서 제목과 설명의 elementFromPoint 검사도 실제 텍스트를 반환했다.

## 연락처
기존 등록 이메일이 Contact에 실제 표시된다. 표시 주소와 mailto 주소가 일치한다. 다섯 너비 모두 보이고 클릭 영역 높이 약71px이며, 클릭·키보드 Enter 활성화 시 기존 mailto를 호출 대상으로 확인했다. 검수에서는 외부 앱을 띄우지 않도록 기본 동작을 가로채 확인했다. 메일 발송이나 외부 메일 앱 연동 성공을 주장하지 않는다. 새 개인정보는 추가하지 않았다.

## 유지한 부분과 한계
기존 결과물 목록·요약 링크·이미지·플레이 기록·연락처는 이미 충분해 유지했다. 새 분석/성과/수치/전문 용어/문서 추가 없음. 외부 메일 클라이언트 및 iOS/Android 실기기는 미검증. 캡처와 검사 결과는 outputs/card-scan/에 보관한다.
