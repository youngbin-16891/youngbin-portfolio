## 2. B — 경기 참여와 적용 범위 교정

- 이벤트가 인정한 경기 완료와 직접 조작 경기 참여를 같은 행동으로 취급하는지 확인한다.
- 실제 사업 목표가 무엇인지 기존 질문 범위 내에서 명시하고 기존 핵심 지표에 모드·플랫폼·조작 방식의 해석 범위를 짧게 보완한다. 감독모드도 유효한 서비스 이용이므로 무가치한 활동으로 단정하지 않는다.
- 9/10 회차의 감독모드 인정 여부는 해당 회차 공식 규칙이나 확인 가능한 실제 동작 없이는 확정하지 않는다. 다른 이벤트 규칙을 옮겨 쓰지 않는다.
- ‘퀵스쿼드는 이용권 보유자만’은 이 이벤트의 1억 퀵스쿼드 보상에 한정한다. 다른 모드의 국가대표 퀵스쿼드와 혼동하지 않는다.
- FC KICK-OFF 이벤트와 KICK OFF 게임 모드, FC 온라인 M과 별도 게임 FC Mobile을 구분한다. 모드 이름 변경 예고는 적용일 확인 전 현재 이름으로 강제 변경하지 않는다.
- 본문/팝업 안내 차이와 서버 동작 오류는 구분한다. 기존 안내 개선의 실행 조건·중단 기준은 유지한다.

## 3. A — 실제 보상 활용과 개인 판단 정밀화

- 보스 수행 가능성은 솔로 스펙뿐 아니라 파티 참여 가능성도 포함한다. 기존 파티 인정 설명과 중복되는 새 표는 만들지 않는다.
- 처음 등장하는 큐브는 정확한 ‘대적자의’ 명칭을 사용하고 잠재능력/에디셔널을 혼동하지 않는다. 동일 품목이라도 다른 시즌 상점의 가격·제한·기한을 여름 PLUS에 그대로 적용하지 않는다.
- 확정 보상 획득과 원하는 잠재 결과 달성은 구분한다. PLUS 미구매는 개인의 추가 지출 가치 판단으로 유지하며 ‘무과금/보상 가치0’로 표현하지 않는다.
- 흔적3배가 기간1/3을 보장하지 않는다는 설명, 2024 계산의 시점 제한, 기본 구매와 PLUS 미구매 진술을 유지한다.
- 남은 기간을 일반 판단 변수로 쓸 수 있으나 사용자가 직접 진술한 미구매 원인으로 추가하지 않는다.

## 4. 반영·검증

새 주장을 늘리기보다 기존 문장을 교체한다. 핵심 분석·출처·구매 증빙·기존 운영 산출물을 보존한다. 영향받은 상세·요약·메인·기존 PDF의 관련 문장만 일치시킨다. 별도 보고서/PDF를 새로 만들지 않는다.

실제 브라우저 PC·모바일에서 변경 구간과 링크를 확인한다. PDF 내용이 달라졌다면 기존 생성 경로로 갱신하고 화면을 확인한다. 테스트하지 못한 환경은 미검증으로 보고한다. 범위에 맞는 기존 빌드·검사만 수행하고 불필요한100회 반복을 품질 증거로 삼지 않는다.

사용자가 기존에 공개 반영까지 요청한 범위에 따라 검증 후 기존 GitHub Pages 배포 방식으로 반영한다. 배포된 변경 내용을 다시 확인한 뒤 링크를 제공한다. 공개 확인이 안 되면 배포 완료라고 쓰지 않는다.
