# C 면접 설명 — 메이플 키우기

연습용 답변. 넥슨의 실제 사건을 처리한 경력으로 설명하지 않는다. 공식 영문 정책의 현행 설명과 과거 사건을 구분한다.

## 30초
환불 사건에서 운영팀이 무엇부터 확인할지 정리했습니다. 신청하면 게임 계정이 제한되기 때문에 미접속을 그대로 자발적 이탈로 세면 안 된다는 점이 핵심입니다. 공지와 FAQ의 조건 설명을 맞추고 거래별 처리와 재문의를 추적하는 모의 문서를 만들었습니다.

## 1분
공식 공지와 FAQ, 실적 서한을 읽고 발생·인지·발표·신청일을 나눴습니다. 초기 공지는 처리 완료 후 제한을, FAQ는 신청 즉시 제한을 설명했고 FAQ 안에도 기간·예외 표현 차이가 있었습니다. 실제로 혼동한 사람이 몇 명인지는 알 수 없어 정책 책임자의 확인과 문구 통일 과제로 잡았습니다. 추가 보상부터 제안하지 않고 공지·FAQ·CS 기준과 거래 대조 절차를 만들었습니다. 사후에는 환불 완료 시간·미처리·재문의를 보고, 활동은 계정 제한 상태를 나눠 봅니다. 환불 완료를 신뢰 회복이나 이탈 감소와 같은 결과로 보지 않았습니다.

## 예상 질문 5개
1. FAQ가 틀렸다는 뜻인가?
표현 차이는 확인했지만 적용 예외나 개정 이력을 모두 모르므로 정책 오류라고 단정하지 않습니다. 현재 영문 페이지 관찰이며 당시 고객 피해의 증거도 아닙니다.
2. 실제 VOC는 몇 명인가?
한 기사 댓글 15개를 확인하고 관련 9개를 포함했습니다. 같은 작성자의 답글도 있어 9명이 아닙니다. 전체 여론 비율로 쓰지 않고 FAQ 질문을 찾는 사례로 사용했습니다.
3. 운영팀 혼자 환불·복구를 결정하나?
아닙니다. 운영은 접수·정리·공지 초안·추적을 하고, 정책·정산·개발·QA와 책임자가 범위와 예외를 확인하는 모의 역할 분담입니다.
4. 환불 요청군 잔존이 낮으면 환불 실패인가?
그렇게 해석할 수 없습니다. 접속 제한이 있고 요청자를 스스로 고른 선택 차이도 있습니다. 제한 계정 수를 따로 보고하고 접속 가능 상태의 행동도 다른 요인과 함께 봐야 합니다.
5. 언제 사건을 종료하나?
원장 대조, 미처리·예외 담당 인계, 재발 검사와 책임자 승인을 확인합니다. 이것은 처리 종료 조건이고 신뢰 회복은 행동·반복 VOC 등 별도 관찰이 필요합니다.

## 먼저 이해할 것
신청 제한과 자발적 이탈 구분 / 환불 처리와 신뢰 회복 구분 / 공식 조치와 본인 모의안 구분 / 과거 공지와 현행 수정본 구분.
근거: C 보고서 S1~S6와 VOC CSV. 실제 내부 지표·전체 여론·정책 예외 판정은 확보하지 못했다.
